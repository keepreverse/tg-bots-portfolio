Интерактивный квиз-калькулятор: задаёт 5–7 вопросов, считает примерный
**диапазон цены** (min–max) и в конце предлагает оставить контакт. Лид сразу
падает мастеру в личку с кнопкой «Написать клиенту».

«Из коробки» бот **поддерживает несколько ниш одновременно** — в демо-
конфиге две категории:

| Категория        | Эмодзи | Что считает                                                  |
|------------------|--------|--------------------------------------------------------------|
| Ремонт квартиры  | 🔨     | Тип ремонта × площадь × состояние + санузел/кухня + сроки   |
| Репетитор        | 🎓     | Предмет × уровень × частота × длительность × формат + сроки |

Перебрендировать под клиента — это **правка одного файла** `data/seed_quiz.json`
(вопросы, варианты, формула). Код квиза трогать не нужно.

## Как пользователь видит флоу

```
/start
  ↓
🎯 Рассчитать стоимость
  ↓ (если >1 категории)
🔨 Ремонт / 🎓 Репетитор
  ↓
▰▱▱▱▱▱ Шаг 1 из 6 — выбор варианта
  ↓ ... после ~половины шагов
🎯 Уже примерно 12 000–18 000 ₽ / мес. Осталось пара уточнений.
  ↓
... остальные вопросы
  ↓
📊 Ваш расчёт: от X до Y ₽
+ повтор всех ответов («Тип ремонта: Капитальный», …)
  ↓
📞 Записаться на консультацию → имя → телефон
  ↓
🔔 Мастер получает в DM лида с кнопкой «Написать клиенту»
```

## Ключевые архитектурные решения

1. **JSON-конфиг = единственный источник правды.** Дерево квиза, веса
   (`weight_min`, `weight_max`), множители (`multiplier`), фиксированные
   надбавки (`flat_min`, `flat_max`) — всё в `data/seed_quiz.json`. Загрузчик
   `quiz_engine.load_quiz_config()` валидирует структуру и падает с понятной
   ошибкой при кривых данных (дубли ключей, отрицательные веса,
   `weight_max < weight_min` и т. д.).

2. **Формула — диапазон, не точка.**
   ```
   total_min = round((Σ weight_min) × Π multiplier + Σ flat_min)
   total_max = round((Σ weight_max) × Π multiplier + Σ flat_max)
   ```
   `flat_*` НЕ умножается на коэффициент — это удобно для «дополнений»
   (например, отдельная цена за санузел). Если по странной причине min > max
   (например, в кастомном конфиге), движок безопасно меняет их местами.

3. **Edit-in-place UX** через одно «главное» сообщение. ID хранится в FSM
   (`MAIN_MSG_KEY`), вместо отправки нового сообщения бот редактирует
   существующее — чат не превращается в простыню.

4. **Кнопка «◀ Назад» работает на каждом шаге** и не разрушает прогресс.
   Возвращает на предыдущий вопрос с сохранением уже сделанных выборов.

5. **«Прогрев» в середине квиза** (`warmup_after_index` в конфиге). После
   ~половины вопросов бот показывает текущий диапазон цены: «Уже примерно
   12 000–18 000 ₽, осталось пара уточнений». Сильно повышает доходимость
   до конца — клиент не уходит, видит что не зря отвечает.

6. **Гард на ссылки в имени и телефоне.** Регулярки + telegram-entities
   ловят `http://`, `t.me/`, `tg://`, `@username` и markdown-ссылки. Защита
   от спамеров, которые часто оставляют в полях контакты-уводилки.

7. **Аналитика воронки.** Каждый шаг логируется в `quiz_events`. В админке
   `/admin → 📈 Воронка` показывается на каком шаге сколько % дошло —
   ценно для клиента, чтобы переформулировать «отваливающиеся» вопросы.

## Команды

- `/start` — главное меню
- `/quiz` — заново открыть выбор категории
- `/cancel` — сбросить текущее заполнение
- `/admin` — админ-панель (только для `ADMIN_CHAT_ID`)

## Админ-панель

```
/admin
├─ 📊 Статистика — стартов, дошедших до конца, лидов, конверсия
├─ 📋 Новые лиды — пагинация по 5
├─ 📥 Экспорт CSV — UTF-8 BOM, отдельные колонки + JSON ответов
└─ 📈 Воронка — по выбранной категории, % дошедших до каждого шага
```

## Запуск

```bash
cd quiz-bot
cp .env.example .env
# отредактируй .env: BOT_TOKEN, ADMIN_CHAT_ID, бренд
pip install -e ".[dev]"
python -m quiz_bot
```

Бот по умолчанию читает квиз из `data/seed_quiz.json`. Путь меняется через
`QUIZ_PATH` в `.env`.

## Тесты

```bash
pytest -q                  # 120+ тестов
ruff check src tests       # линт
```

Покрытие включает:
- **quiz_engine** — парсер конфига (валидация, дубли, диапазоны),
  расчёт цены (веса + множители + фиксированные надбавки), эджи (партиал-
  прогресс, неизвестный ключ, min > max);
- **validators** — URL-гард на имя, нормализация телефона;
- **db** — события, лиды, пагинация, CSV/UTF-8 BOM, воронка;
- **views** — прогресс-бар, экраны, состав клавиатур, конверсия в `/admin`;
- **handlers** — построение роутеров, склонения «лид/лида/лидов», sanity на
  callback-data префиксы.

## Кастомизация под клиента

1. Открой `data/seed_quiz.json`.
2. Перепиши `categories` под нишу — оставь одну, добавь несколько, замени.
3. Цена считается по формуле `(Σweights) × Π multiplier + Σflat`. Подкрути
   `weight_min` / `weight_max` / `multiplier` / `flat_*` по вкусу.
4. `warmup_after_index` — индекс вопроса (с 0), **после** которого показать
   экран «уже примерно X–Y ₽».
5. `price_unit_label` — суффикс в выводе цены (например, `" / мес"` для
   репетитора, `""` для проектной работы).
6. Перезапусти бота — изменения подхватятся.

Технически: код квиза не зависит от количества и состава категорий. Если в
конфиге одна категория — экран выбора скипается, пользователь сразу попадает
в квиз. Если несколько — на старте показывается чистый «Что считаем?».
